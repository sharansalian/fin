2 The entity & Razorpay — your “one payee”

A Razorpay account is free. What you actually register (and pay for) is the business entity + current account Razorpay sits on. That is what makes users pay “Saachi Technologies,” never “Sharan.”

Register a Private Limited Company

Not a sole proprietorship. For a dating/matrimony product specifically:

  • Limited liability — strangers meet strangers + sensitive personal data. If anything goes wrong, a Pvt Ltd shields your personal assets. A proprietorship does not. Non-negotiable here.
  • Trust signal — “pay to a registered company” is the clean/safe brand.
  • Future-proof — hiring, fundraising, going global all need a company anyway.

RBI note: UPI Autopay handles recurring sub-₹15,000 charges cleanly — perfect for your premium plans. Keep an eye on the e-mandate rules; Razorpay Subscriptions handles most of the compliance for you.

5 MVP blueprint & data model

Reuse what you already run: Firebase Auth + Firestore + Cloud Functions + your packages/core. Razorpay replaces Lemon Squeezy. Ship phases in order — trust foundation before the dating loop.

Feature phases

Phase 0 · Trust foundation (the wedge)build first
  • Phone OTP signup (no anonymous accounts)
  • Mandatory selfie + photo verification → “Verified” badge (AI match first, human review queue)
  • Optional Govt ID / DigiLocker verification → gold “ID Verified” badge
  • Women-first privacy: blurred photos until mutual interest, screenshot block, zero contact-info exposure
  • Report / block + a moderation queue (Cloud Function + admin view)
Phase 1 · Core matrimony loopMVP launch
  • Guided profile creation (religion, community, mother tongue, education, profession, location, about, photos)
  • Discover feed + filters (community, religion, age, location, profession)
  • Daily curated matches
  • Send Interest → Accept / Decline → chat unlocks on mutual interest
  • Premium gating: free = limited interests/day & no chat initiation; premium = unlimited + initiate + “who liked you”
Phase 2 · Monetize & deepen trustafter liquidity
  • Razorpay Subscriptions (UPI Autopay) — monthly / quarterly / annual
  • “Verified-only mode” — premium filter to show only ID-verified profiles
  • In-app video call (number stays private)
  • Boost / Spotlight one-time purchase
Phase 3 · Diaspora / globalscale
  • NRI filters, multi-currency, timezone-aware matching
  • Localization + community-specific onboarding

Firestore data model

// Reuses your users/{uid} pattern from Pocket
users/{uid}
  profile:      { name, dob, age, gender, height, religion, community,
                  motherTongue, education, profession, incomeBand?,
                  location:{ city, country, geo }, about, photos:[url] }
  preferences:  { ageRange, religion[], community[], location[], heightRange }
  verification: { phone:true, email:bool, selfie:'pending|passed|failed',
                  govId:'none|pending|verified', badge:'none|verified|gold' }
  premium:      { plan:'free|monthly|quarterly|annual', status,
                  expiresAt, razorpaySubId }
  privacy:      { blurPhotos:true, screenshotBlock:true, hideFromSearch }
  safety:       { reportsAgainst:0, blockedUsers:[uid], shadowBanned:false }
  counters:     { interestsSentToday, dailyLimit }

interests/{interestId}      // the like / propose action
  { fromUid, toUid, status:'sent|accepted|declined', createdAt }

conversations/{convId}      // created only on mutual accept
  { participants:[uidA,uidB], lastMessage, lastAt, unlockedBy }
  messages/{msgId}  { senderUid, text, sentAt, read }

reports/{reportId}          // moderation queue
  { reporterUid, reportedUid, reason, evidence?, status:'open|actioned|dismissed' }

verifications/{vid}        // KYC audit trail (Cloud Function writes)
  { uid, type:'selfie|govId', provider:'idfy|digio', result, ref, at }

subscriptions/{subId}      // Razorpay webhook target
  { uid, razorpaySubId, plan, status, currentPeriodEnd }

Security-rule principles

  • Verified-gate writes: only verification.phone==true can send interests; only selfie=='passed' appears in Discover.
  • Premium-gate chat initiation: a Cloud Function (not the client) creates conversations and enforces free-tier limits — never trust the client for gating.
  • Gender / privacy visibility: photo URLs resolve through a Function that honours blurPhotos until mutual interest.
  • Webhooks server-side only: Razorpay signature verified in a Cloud Function before touching subscriptions — mirror your existing lemonWebhook pattern.
Reuse map: Auth → same. Firestore users/{uid}/... → same shape as Pocket. sharePreview/OG pattern → reuse for shareable profile links. lemonWebhook → becomes razorpayWebhook. Your whole Cloud Functions skeleton ports over.
